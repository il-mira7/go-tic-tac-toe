# 🎮 go-tic-tac-toe

Крестики-нолики против идеального бота: веб-игра на Go, в которой противник выбирает ход алгоритмом **минимакс**. Сыграть вничью — уже хороший результат.

Одностраничный интерфейс встроен в бинарник через `embed`, REST API — на gin, граф зависимостей собирается uber-fx. Состояние партий живёт в памяти в потокобезопасной коллекции.

## Запуск

```bash
cd src
go run ./cmd/app
```

Открыть [http://localhost:8080](http://localhost:8080). Порт переопределяется переменной `PORT`.

## API

| Метод | Рут | Описание |
|-------|-----|----------|
| `GET /` | одностраничный UI игры |
| `POST /game/:uuid` | ход игрока: `{board, row, col}` → `{game_id, board, status}` |

Клиент присылает всё поле целиком, сервер проверяет, что предыдущие ходы не подменены, фиксирует ход игрока и отвечает ходом бота.

## Архитектура

Слоистая структура зафиксирована учебным заданием (Go Bootcamp, School 21): domain → infrastructure → web плюс отдельный DI-слой, интерфейсы на каждом шве и мапперы между представлениями данных.

```
src/
├── cmd/app/            — точка входа
├── internal/
│   ├── domain/         — правила игры: поле, статусы, минимакс, валидация ходов
│   ├── infrastructure/ — хранилище партий (sync.Map), репозиторий, мапперы
│   ├── web/            — gin-сервер, REST-хендлеры, мапперы, UI
│   └── di/             — сборка зависимостей (uber-fx)
└── public/             — index.html, встраивается в бинарник
```

## Что я сделала бы иначе

- Для приложения на ~600 строк четыре слоя и мапперы между каждым — тяжеловато; хватило бы `web → domain → хранилище` с одним интерфейсом на границе хранилища.
- Модель игры маленькая, а представлений у неё три (domain, storage, web) — дублирование мапперов ощущалось бы сильнее на проекте побольше, здесь его проще схлопнуть.
- При этом интерфейс репозитория оказался не лишним: следующий этап меняет `sync.Map` на PostgreSQL — доменный слой при этом трогать не придётся.

## Этапы развития

Проект развивается по нарастающей, стадии публикуются по мере готовности:

- ✅ **Этап 1** *(вы здесь)* — игра против бота-минимакса: REST API, состояние партий в памяти, встроенный веб-UI
- 🔜 **Этап 2** — PostgreSQL вместо in-memory, регистрация и вход, партия на двоих
- 🔜 **Этап 3** — JWT-авторизация, история партий, таблица лидеров
